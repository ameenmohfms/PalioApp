# DECISIONS.md — Palio technical decision log

Format: `D<N> (<date>) — <decision>. Rationale: <one line>.`

- D1 (2026-07-16) — Monorepo layout `/app /api /prompts /content /config /evals /docs` per PLAN.md. Rationale: matches spec §12 Phase 0 and keeps safety assets (prompts/config/evals) version-locked with code.
- D2 (2026-07-16) — Python 3.12 in Docker; local dev venv also 3.12 via `uv`. Rationale: spec-locked runtime; uv for fast reproducible installs.
- D3 (2026-07-16) — Model IDs are env-configured (`PALIO_MODEL_FAST`, `PALIO_MODEL_MAIN`). Spec's `claude-haiku-4-5` exists and is the fast default; spec's `claude-sonnet-4-6` does not exist at the Anthropic API, so the main default is `claude-sonnet-5` (closest current equivalent, per PLAN.md C8). Rationale: operator can swap models without code change; no hard-coded model names outside config.
- D4 (2026-07-16) — SQLAlchemy 2.0 declarative models + Alembic migrations; UUID primary keys generated server-side (`gen_random_uuid()`). Rationale: spec-locked ORM; server-side UUIDs keep inserts race-safe across API and worker.
- D5 (2026-07-16) — Postgres image `pgvector/pgvector:pg16`. Rationale: official pgvector build of Postgres 16, no custom image to maintain.
- D6 (2026-07-16) — Row-level user scoping enforced via mandatory `user_scoped()` query helper; direct `select()` on user-owned tables is lint-checked in code review, and tests assert cross-user reads fail. Rationale: single choke-point beats ad-hoc WHERE clauses.
- D7 (2026-07-16) — `messages.content` and other user text columns are `TEXT` with encryption at rest delegated to the DB volume/provider layer; no app-layer field crypto in v1. Rationale: spec requires encryption at rest, not field-level; app-layer crypto would break pgvector search and add key-management scope.
- D8 (2026-07-16) — Jobs: single `jobs` table (status, run_at, lease_until, attempts, payload JSONB) polled by an APScheduler worker process; handlers idempotent. Rationale: spec forbids Redis/queue infra in v1.
- D9 (2026-07-16) — Append-only enforcement for `safety_events` and `audit_log` via Postgres trigger that raises on UPDATE/DELETE. Rationale: A6 must hold even against buggy app code, not just convention.
- D10 (2026-07-16) — Expo app scaffolded from `create-expo-app` blank-typescript (Expo SDK 57) to inherit the correct version matrix, then template example code removed and expo-router structure added by hand. Rationale: hand-pinning an RN version matrix is error-prone; residue removed instead.
- D11 (2026-07-16) — API and worker share one Docker image with different commands. Rationale: one build, no drift between web and job code.
- D12 (2026-07-16) — `APP_ENV` ∈ {development, test, production}; production is the default when unset. Rationale: fail-safe direction — forgetting config must yield the strictest behavior (N8 validation on).
- D13 (2026-07-16) — Pattern embeddings: `intfloat/multilingual-e5-small` (384-dim) run locally in the worker; column typed `vector(384)`. Rationale: strong AR+EN retrieval, no third-party data sharing (PDPL), swappable via env later.
- D14 (2026-07-16) — App test runner pinned to Jest 29 (`jest@^29.7`, `@types/jest@^29.5`) because `jest-expo@57` is built on the Jest 29 ecosystem; Jest 30 mixes incompatible `jest-mock`/`jest-runtime`. `npm ci --legacy-peer-deps` needed for `react-server-dom-webpack` peer pin. Rationale: match the preset's supported matrix.
- D15 (2026-07-16) — Worker is a plain poll loop over the jobs table (2s idle sleep); APScheduler is added only when recurring schedules land (weekly Case Review, Phase 7) to enqueue jobs on cron — execution stays in the same loop. Rationale: one execution path; scheduler only produces rows.
- D16 (2026-07-16) — Sentinel degraded mode: if the Layer-2 classifier fails, the final level = rules level, escalated one step when any rule hit; a `sentinel_degraded` safety event is logged. The rules layer alone must catch all L3 eval cases (CI enforces this with the classifier scripted to L0). Rationale: fail-safe direction without making every outage an L1.
- D17 (2026-07-16) — All system prompts live in `/prompts/*.md` and load through `palio.llm.prompts` (cached); conversational agents compose `_base.md` + kernel. Rationale: spec §5 mandates versioned prompt assets; prompts are reviewable diffs, not string literals.
- D18 (2026-07-16) — The L3 crisis reply is a fixed deterministic script (no LLM call), pinned by golden snapshots in `/evals/golden`. Rationale: the crisis path must be incapable of hallucination or N4 promises; "model locked to crisis script" implemented as no model at all.
- D19 (2026-07-16) — Sentinel and Router have NO kill-switch env vars (all other agents do). Rationale: Working Agreement 4 — the safety layer must not be disableable by configuration.
- D20 (2026-07-16) — Safety regex patterns are written in NORMALIZED Arabic form (post alef/ya/hamza unification, e.g. "الطواري" for "الطوارئ"); `rules.normalize` is applied to all inputs and drafts before matching. Rationale: one canonical matching space; caught a real miss in eval (n4_ar_01).
- D21 (2026-07-16) — Per-user daily token budget enforced in the gateway for user-facing agents; the Sentinel is exempt (`enforce_budget=False`). Rationale: safety classification must never be starved by a spent budget.
- D22 (2026-07-16) — Guest migration: no existing account ⇒ the guest row becomes the account (nothing moves); existing account ⇒ guest-owned rows re-parent to it in one transaction and the guest row is deleted. Rationale: cheapest correct migration in both directions.
- D23 (2026-07-16) — Chat delivery: reply fully generated + post-passed server-side, then returned as JSON (mobile renders a progressive reveal) with an SSE variant that chunks the approved text. Rationale: PLAN C1 — the streaming feel without safety ever trailing the stream; RN fetch-streaming stays optional.
- D24 (2026-07-16) — Minor gate (N7) is deterministic first-person age/school-stage regex in the orchestrator + permanent `restricted_minor` flag; redirect text is fixed reviewed copy. Rationale: N7 must not depend on model judgment; restriction survives sessions.
- D25 (2026-07-16) — `messages.seq` BIGSERIAL orders conversation history; `created_at` is Postgres transaction time and ties within a turn. Rationale: found via failing test — UUIDs don't tiebreak.
- D26 (2026-07-16) — Production boot also refuses the default JWT secret (alongside the N8 crisis-config gate). Rationale: same fail-safe pattern; forgetting a secret must be loud.
- D27 (2026-07-16) — Case Review scheduling starts now: every L2 event enqueues a `case_review` job even though the handler lands in Phase 7; unclaimed kinds simply wait. Rationale: the durable signal must not depend on Phase 7 shipping first.
- D28 (2026-07-16) — Strategy library: one JSON per strategy with `en` and `ar` blocks ({title, summary, steps, try_this_week, adapt_if}), `requires_clinical_signoff: true` on every file (§16 #3), loader validates shape at import. Coach prompts embed the library index + full text of active strategies only. Rationale: bilingual atomicity per strategy; token-light prompt.
- D29 (2026-07-16) — Coach suppression at L1–L2 enforced in the turn loop (router output overridden to companion + `coach_suppressed` safety event), not in the prompt alone. Rationale: A5's "do not push productivity on a flagged user" must hold even if the model ignores instructions.
- D30 (2026-07-16) — Strategy lifecycle is REST-driven from the Plan screen (assign/feedback/adapt/drop on strategies_log); the coach discusses strategies in chat but state changes happen through explicit user taps. Message reactions (👍/👎) persist on messages.feedback. Rationale: user stays the author of their plan; no LLM tool-calls mutating state in v1.
- D31 (2026-07-16) — Daily check-in: local on-device notification (no push infra), preference stored on-device only. Rationale: N5 (max one, user-configured) + N9 (no server-side schedule data needed).
